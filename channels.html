NetworkChuck

Main video: You've Been Using AI the Hard Way. 2,248,668 views. About 34 minutes. source. Written guide: ai-in-the-terminal. Lesson from the public transcript.

What the video is

He moves the model out of the browser and into the terminal, because the terminal can see your folders. The browser cannot, unless you paste. Five segments.

Segment 1, Gemini, from 1:09

Install the Gemini command-line tool. Make a folder. Start Gemini. Log in with Google. Ask it something small. It can write a file in that folder. Type slash and it can write a context file, gemini.md, so the next session already knows the project. He shows it reading notes that are already files, including an Obsidian vault. Free tier. This is the first tool, not the only tool.

Segment 2, Claude Code, from 8:43

Install, then run claude. It needs Claude Pro, about $20 a month in his telling. A context file, claude.md, holds the standing order. Slash context shows how full the window is. Slash agents makes a worker with its own fresh window, so the main chat does not bloat. He makes a homelab agent and a critic agent. Headless mode, claude -p, is for a script. The skip-permissions flag exists. Do not use it on a folder that holds client notes.

Segment 3, three tools, one folder, from 17:59

Gemini, Claude Code, and Codex open in the same directory. Each has its own context file. They do not share a chat. They share the folder. That is the handoff.

Segment 4, from 20:31

A closer agent writes a summary and commits. A critic agent scores the work. Git is the history. Treat the notes like code.

Segment 5, OpenCode, from 26:29

OpenCode is the open tool. It can point at a local model, he names Llama, or at a Claude login. This is the door for Qwen on your ROG box. Config lives in a json file.

What to copy

One folder. One context file. Gemini or OpenCode first, because they can be free or local. Claude Code when the job needs agents. You read the file before it is trusted.

IndyDevDan

Cited as the principle-first Claude Code teacher. Channel: @indydevdan. Individual timestamps were not opened this pass, so this lesson stays on the methods secondary pages attributed to him.

What he is for

Not hardware. Not a model pick. He teaches how the harness is programmed: a CLAUDE.md standing order, skills as reusable commands, subagents, and git worktrees so two agents do not edit the same files.

The rule

One skill, one job. The incident skill is a standing order: use only the note, write missing if a fact is absent, never mark the report approved. A worktree is a second copy of the folder so a second agent cannot overwrite the note.

What not to assume

A feature named in a roundup is not proof it is in a specific video. Open the video before you treat a command as his.

The terminal video, full guide

NetworkChuck · 2,248,668 views · 34 minutes · video · written guide

What this video is

This is not a model review. It is a change of workplace. He is moving the model out of the website chat and into a folder on the computer. The website chat cannot see your files unless you paste them. The terminal can. Once the model can read a file and write a file, the chat stops being the product. The file is the product. That is the only idea in the video. Everything else is him proving it with four tools.

Words he uses

The terminal is a text window that runs commands. A context window is how much text the model can look at in one turn. The website hides that number. The terminal shows it. A context file is a note in the folder, named gemini.md or claude.md, that the next session reads so you do not paste the old chat. An agent, in this video, is a second worker with its own fresh window. Git is the history of the folder.

Segment 1, minute 1 to 9. Gemini

He starts with Gemini because the account is free. He installs the command, makes a folder called coffee-project, starts Gemini, and logs in with Google. He asks a small question. Then he lets it write a file in that folder. That write is the test. If the tool cannot write a file, the rest of the video does not matter. He then uses a slash command to write gemini.md. The next session loads that file. He also points it at an Obsidian vault, which is just a folder of notes, to show that notes you already have are readable without pasting.

Segment 2, minute 9 to 18. Claude Code

Claude Code is the tool he uses when the job needs workers. It needs a paid Claude login, about $20 a month in his telling. He writes claude.md the same way. Slash context shows how full the window is. Slash agents makes a worker with a new window, so the main chat does not fill up. He makes a homelab worker and a critic. Headless mode, claude -p, lets a script ask one question and quit. There is a flag that skips the permission question. Do not use that flag on a folder that holds a client note.

Segment 3, minute 18 to 20. Three tools, one folder

He opens Gemini, Claude Code, and Codex in the same directory. They do not share a chat. They share the files. Gemini does the long read. Claude writes the script. Codex does a second pass. If you keep one sentence from this segment, keep that.

Segment 4, minute 20 to 26. Closer and critic

A closer writes a summary and commits. A critic scores the work. He has one score a script 8.2 out of 10. The score is his demo, not a standard you have to copy. The useful part is two files: the original, and the review.

Segment 5, minute 26 to the end. OpenCode

OpenCode is the open tool. It can point at a model on your machine, he names Llama, or at a Claude login. The setting lives in a json file. This is the door for a Qwen file on the ROG box.

What you do with it

Make one folder for the incident desk. Put one note in it that says the model may only use the officer's write-up, must say missing if a fact is absent, and must not mark the draft approved. Run Gemini or OpenCode. Have it write a second file from a fake note. Read that file. Stop. Do not install the other three tools on day one.

Model on your machine

NetworkChuck · about 2.7 million views · video

What this video is

The terminal video used a company login. This one puts the model file on the computer. Ollama is the program that holds the file and answers on a local port. Open WebUI is a window that talks to that port. The chat looks like a normal website. The note did not have to leave the machine.

The two steps he mixes

Step one is the local window. That is the lesson. Step two is putting that window on a domain so a phone can reach it. A domain is a door. An incident note does not go through a door you do not control. Stop after step one.

What you do

Install Ollama. Pull a small model. Ask one harmless question. Write down the tag that answered. Your cards are 8 GB each. They do not add up to 16 by themselves. If a larger file does not fit, leave it. Pair this with the 15-minute Ollama lesson before a 27B file.

The 15-minute model lesson

Tech With Tim · about 1.2 million views · video

What this video is

The install film for the model file. Ollama loads a file onto the card. The card's memory decides what fits. Context length is how much text the model will look at. A longer window uses more memory and can push a model off the card into system RAM. RAM works. It is slower. A slowdown you did not time is not a result.

The copies

Q4 is the smaller, fuzzier copy. Q6 is cleaner and heavier. A report wants the cleaner copy if it fits. A chat can live with Q4. Write down the tag, the quant, and the context length after the first successful prompt. The next run uses that same line.

What you do

Small file. One prompt. Then a fake incident note. The draft is a second file. Missing stays missing. The 27B file is a later test, not the start.

The order of work

This is the desk the other nine guides are for.

An officer writes what they saw. That note is a file. A small local model may read only that file. It writes a second file. If a fact is not in the note, the draft says missing. You sign it. Nothing sends itself.

Then, and only then, a page with three fields for the stream, filled from a file you approve. A clip tool after that, and only from an approved draft. Shannon's stage files are the same shape, used on an app you own. Ruflo, Camofox, Mimic, and the comment-word funnels are not step one.

Videos that never came back with a title are not in this library. A channel count is not a list. Two of your reels returned no caption. They are not filled in.
